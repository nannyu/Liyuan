# 预设分拣 AI 转换 —— 三预设通读经验与规格

2026-08-11。用户令「不能靠脚本转换,必须让模型转换;导入预设自动调用 AI 转换,进度前端可视」。
本文是三次手工通读(双人成行 242 / TGbreak 91 / 夏瑾 23,共 356 块)的经验总结，
也是 AI 转换 SYSTEM_PROMPT 的判据来源（文案即规格）。手工 v2 是 AI 转换的验收基准（TDD）。

## 〇、2026-08-12 收缩定案（高于本文其余部分，冲突以此为准）

用户复盘：「搞这么多干嘛，预设对梨园本就是污染，不如全放提示词让用户自己删」。收缩成三条：

1. **去处轴只有两处 + 状态栏 + 删**，不做四去处精致规划：
   - 送模的散文（破限/配置/文风/NSFW/方法论全部）→**系统提示词**。skill 与提示词页签合并（前端 `V2_FAMILY_DEST` 五家族全映射 prompt）。
   - **状态栏**（输出合约家族）不属于提示词——进它会复活 8/10 双指令源事故，归输出合约声明步。
   - **删**＝旧执行环境协议税，前端列审阅，用户拿现成的逐块开关自己关（不新增删除机制）。
   - 参数照旧数据投影。
2. **预设不再产 skill**（`preset-skill.ts` 投影式「预设→skill」制度上退役——它从来不是真 skill：blocks/*.md 不进 L1 索引、不上 skill_read 货架）。预设 skill 页签让位给**真 skill 库编辑器**。
3. **skill 编辑器**（`web SkillLibrary` + `src/stage/skill-store.ts` + `/api/stage-skills`）：写的就是 `scanSkillFiles` 读的 `skills/<目录>/SKILL.md`，编辑器产物＝引擎消费物，保存后下一拍装载即生效（引擎每拍现读）。字段＝名称 + 简要说明(检索触发面,占位提示「只写何时用」) + 常驻开关 + 正文。写作类 skill 好写：简要说明让 agent 检索 + 主要内容。
4. **引擎送达＝冻结区,未动**：预设送达仍走 `preset-split.ts` v1 拆层表 + 四类兜底,今日合并纯展示层。「预设 skill 块改常驻送达」须用户明示。
5. **AI 分拣仍判九家族**(本文 §一/§二判据不改),前端把家族映射成两去处即可——「分拣一行不用重写」。

下文 §一~§四是九家族分拣的原始规格,仍是 AI 分拣的判据来源,阅读时按上面第 1/2 条把家族折算成去处。

## 二、判据（八条铁则，直接写进 SYSTEM_PROMPT）

**A. 判身份，不判载具。** 同一内容可裹在 setvar、html 注释、YAML 伪代码、【问题】问卷、`<tag>` 里——
载具是执行环境的产物。判家族只看内容说什么，不看它怎么包装。
（反例：双人成行禁词表被旧 police 正则误杀；TGbreak 活人感裹在 COT setvar 里差点被当协议删。）

**B. 互斥组是第一大坑。** 人称/抢话/推进速度/文风/字数/基调都是「同一维度的多个值」，必须成组。
判据三选一：多块写同一个变量 / 块名带「N 选 1」「3 选 1」/ 前面有分隔标题块领起。
（反例：把人称九块判成九个 skill——它是一个单选维度，属配置不属 skill。）

**C. COT 模板 vs 被引用内容。** TG/夏都是「COT 主模板 + 被 getvar 引用的知识块」。
主模板（输出 thinking/draft_notes 的问卷骨架）= 删；被塞进问卷的知识块按内容身份归家族。
判据：块本身是「思考问卷格式」→删；块是「被引用的知识/规则」→看它讲什么。

**D. 装配包装标签删。** `<Story setting>`、`<wfeeling>`、`<{{user}}设定>` 这种纯开/闭标签＝历史结构装配，
梨园自持。判据：内容只有 XML 开闭标签、无实质指令。

**E. 机制覆盖即删。** 摘要（compact）、变量更新（记账/MVU）、抗注入宣言（对抗 harness 本身）、
防不读世界书（lorebook）——梨园有自己的机制覆盖它就删。判据同第四问：梨园有无机制负责它。

**F. 排练外显删。** 每段/每句正文前强制输出 html 注释打草稿（TGbreak 对白活人化/边写边思考、双人成行草稿@Kemini）＝排练外显的载具，删。内容若有价值（对白口语化等）已在方法论家族另有归属。

**G. 删要保守，兜底归 skill。** 删＝内容蒸发（代价大）；错归 skill/方法论只是上错货架（内容还在，可改判）。
拿不准时归方法论，不归删。

**H. 自定义空槽归对应家族。** 文风槽/杀X槽/合约格式槽——不删，用户填入即生效。

## 三、三预设差异（家族比例与结构指纹）

- **双人成行**（11 万字，最全）：文风库巨大（41 块 3 万字，几乎全 OFF＝备胎库）；旧 police 误杀最多（6 块救回）；靠 vars 表把 setvar 里的有效载荷救活。启用面里 COT 协议占 44%。
- **TGbreak**（3 万字）：COT 插槽式——`gs-*`/`COT-*` 变量在「别关」块统一清零、在功能块 setvar 注入，[072] 基础思维是主模板消费全部插槽（它死则上游插槽全死）；[082] 检查格式统一拼装格式栈；咪咪吐槽 catsay 是特色输出块。
- **夏瑾**（5.5 千字，最凝练）：拉康式精神分析框架（欲望-感性-知性-理性，独特作者理论，看不懂≠删）；COT 首尾骨架 + 中间知识块被引用；无独立字数参数块（字数目标内嵌思维链尾）。

结论：家族类目在三个截然不同的预设上稳定复现，判据可迁移＝可交给声明模型执行。差异只在比例与载具风格，正是「判身份不判载具」要吸收的方差。

## 四、AI 转换机制（形状 = contract-declare.ts 的平行件）

**触发**：导入预设（POST /api/presets/import）后自动起后台分拣任务；也可对已有预设手动重跑。
**调用**：分批送料（每批 N 块，含块名+内容+enabled+互斥线索），逐批调模型，模型按本文判据输出每块 family + 组建议。
**进度**：任务写内存进度（phase/done/total/error），前端轮询 `GET /api/preset-sort/status` 显示进度条；完成后刷新预设面板，v2 家族视图出现。
**产物**：`skills/预设-<slug>/manifest.v2.json`（schema=sorting-v2，与手工基准同构）。指纹＝预设块内容+开关；命中缓存不重跑。原始应答落盘（`.liyuan/preset-sort.raw.txt`）便于验尸。
**回退**：分拣失败静默——前端回落两分法，引擎送达永远走 v1，AI 转换只是展示层的分类升级，零风险接线。
**验收**：新功能跑三预设，与本文手工基准逐块对（families 吻合率、互斥组召回）。判据偏保守：错归无害（可改判），删要少。

**铁律核对**：①不堆叠提示词——SYSTEM_PROMPT 是新通道的唯一主人，不往送模面加话；②不堆叠注入——分拣是装载期旁路声明，不在送模链新增注入点；③不堆叠架构——用模型声明替代 splitTable 手工表/四类兜底正则（名单只减不增）；④整体性思考——全集=任意预设的任意块，负责人=声明模型，没见过的卡上表现=按判据归类、错在可见可改的 manifest 数据里。
