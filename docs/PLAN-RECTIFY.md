## 0. 三问定案总览

**问题一（提示词与注入混淆）**：输出架构与扮演双向混淆。harness 送模文案在教扮演（内置迷你预设、篇幅四处、教练话术、状态栏七处催告）；节拍器三重死板（位置＝每段必停、内容＝固定仪式卡、通过条件＝三道门禁）。定案：骨架留（工件化＋断点＋代码执行），节拍器拆；送模面收缩为五注入；修复是伪命题，违规单驱动的修复链整体退役。

**问题二（预设污染）**：预设＝酒馆唯一可编程槽里「用散文写的装配程序」，其内容为旧执行环境（无状态/无工具/每轮重发/一次生成）而写；梨园每造一个真机制，预设里就多一层违禁品。定案：分拣五去向——留驻（破限/边界，原文直通）、迁 skill（文风/方法论）、退场（COT/变量协议/自检/摘要/假对话）、数据化（状态栏/点评类输出模块→输出合约）、参数（samplers 照旧）。分拣机制从识别器换成装载期一次性模型声明。

**问题三（skill 设计）**：经实地解剖（superpowers / ui-ux-pro-max / SoftwareCopyright-Skill / codex 官方文档 / agentskills.io 标准，材料在 `E:\silly-agent\_skill-research`）：采标准原样；三级渐进披露；触发走结构钩子（梨园的 harness 优势——断点送索引，不学 superpowers 的说服力轰炸）；场面包＝触发表＋核心写法＋示范段＋反模式表；写包走 TDD（无 skill 基线→写→复测→堵漏）。

## 1. 判据集（本契约的裁决规则）

- **P1 产权线**：形式与时机归 harness（你在哪一步、哪些动作可用、日程），内容与方法归署名数据（预设/卡/skill）。改完后 **harness 源码里不再有一句扮演**——扮演的每个字都有署名主人。
- **P2 落笔之后只送事实，不送评价**。判定注入送进度与字数（事实），谢幕注入送日程，验收回执送陈述；违规清单是评价——死。
- **P3 修复是伪命题**：违规单驱动的正文修复不存在；质量投资全部在落笔前（思考空间＋skill＋素材）。落笔后唯一合法的回喂是**新信息**（ask 答案、检索结果、世界事实）。
- **P4 工具用法进工具描述，不进轮次卡**。「路标写到发生什么的抽象层」「一段一交」这类通道契约写进 beat_plan/draft_append 的 description——那是通道自己的说明书，不是每轮的指令。
- **P5 输出模块三分**：时机归 harness（断点日程），格式归合约（数据），内容归模型（演出）。预告式催告全部非法——日程不需要预告。
- **P6 名单只许收缩**；每个现存名单的替代物是合约字段。合约立起后，显示折叠/历史剥离/谢幕点名全部从合约推导。
- **P7 自由度匹配**（Anthropic 官方 degrees-of-freedom 框架背书）：脆弱且必须一致的操作→代码/合约零自由；多路可行依赖语境的创作→散文高自由。RP 的「这段怎么写」是开阔平原，harness 不设护栏。

## 2. 终态送模面（改完后模型看到什么）

### 2.1 静态 system prompt＝数据路由骨架，零 harness 扮演话语

保留（全部是素材通道或架构协议）：

1. `# 舞台` 一句（你扮演 X，用户扮演 Y——数据）；
2. `# 角色卡`（description/personality/scenario/mesExample——卡数据原样）；
3. `# 用户扮演`（persona——数据）;
4. `# 世界设定`（常驻世界书——数据）；
5. `# 工作方式`（纯协议，≤5 行，零扮演词）：

   > 每拍第 1 轮用 `beat_plan` 列路标（没有戏的拍可 `draft_write` 一次交完）；正文用 `draft_append` 逐段写在稿纸上，写完 `draft_seal` 收笔。剧情走向要用户拍板时随时 `ask`。每轮注入的【进度】【判定】【记账】【谢幕】是当前状态，以它为准。

6. `# 工具清单`＋`# MCP 外设`（能力索引——协议）；
7. `# 可用 skill` 索引（M-R2 起：name — description 列表，L1 披露）；
8. `# 消息流约定`（【开场】【前情提要】【世界状态】等标注语义表——协议）；
9. **预设留驻内容：原文、原序、原通道，零 harness 引导语**（A 破限＋C 边界；文风类迁 skill 后不再进此区）；
10. 卡作者附加指令（systemPrompt——数据）。

**删除**：`# 叙事与文风` 全段（含无预设兜底分支）、`# 输出结构` 全段、`# 怎么演这一拍` 的作家咏叹调与分步教学、状态栏描述与 buildStatusBarPrompt。

### 2.2 每拍末端注入＝事实块

保留：【世界状态】【登场名录】【活跃面板】【相关设定】【设定集索引】（数据）；【预设末端指令】原文直通（零归拢零引导语）；语言一行（config 事实）；字数一行（`本拍约 X–Y 字`，纯事实无「朝这个量落笔」类指令）；【语言纠正】（自愈事实，触发才有）。

删除：【导演备注】作为容器解散（主权行迁默认预设；「演完即停」句删——判定/谢幕的日程已表达时序）；【状态栏】块（谢幕注入替代）；【思考的用法】（rehearsalGuard 注入整体删——排练问题由工作循环结构消化，不再用注入治）。

### 2.3 五注入（轮次层全部送模文案，文案即规格）

**规划卡**（每拍第 1 轮，随末端注入送达，工作区空时）：

> 【第 1 步·规划】本拍还没有计划。读题、探索（工具自取）之后用 `beat_plan` 列路标。没有戏的拍可 `draft_write` 一次交完；用户本轮在求方向/递笔的，直接 `ask`。

**进度行**（每轮替换语义，替代开工卡/回看卡）：

> 【进度】路标 2/5「褪衣取砚」；已演 3 段，正文约 1240 字（目标 2000–4000）。

无字数目标时省略括号。无任何教学、无①②③④、无「构思/回看/评估」指令——下一步做什么是模型的判断。

**判定注入**（路标全部演完时，替代续写卡＋收笔评估卡）：

> 【判定】路标已演完，正文约 X 字（目标 Y–Z）。续写、`ask`、或 `draft_seal` 收笔——你判断。

**记账注入**（seal 之后（含兜底封笔）第一件事；8/10 补定——记账此前没有席位，靠谢幕卡捎带＋场记兜底旁路。本席位同时是 MVU/UpdateVariable 退场判决的兑现：账本机制获得日程保证的时刻）：

> 【记账】已封笔。核对本拍变动并落账：世界状态用 `world_state_update`（物品/时间/位置/关系），表格与面板用 `panel_write` 同步。没有变动就直接停。

记账轮结束（模型停止调用写账工具）→ 谢幕注入。**状态栏因此永远渲染已落账的最新状态——顺序由日程保证，不靠嘱咐。** 允许的结构性优化：本拍已有落账（ws.patches／面板写入非空）时可跳过本注入——判据必须是结构信号，禁止文本识别。场记兜底（runScribeTurn）随之降级为真兜底：触发条件不变（本拍零落账才旁路补账），预期触发率大降，记录触发数据决定退役（承 M-B 待决）。

**谢幕注入**（记账轮之后，输出合约非空时，替代谢幕卡＋程序化谢幕＋收场卡）：

> 【谢幕】记账已毕。输出本拍格式块：`<state1>` 状态栏、`<catsay>`。输出完本拍结束。

合约为空→不注入，拍自然收束。**这是全仓库唯一提到状态栏的送模文案**（七处预告催告全部退役）。

### 2.4 工具回执瘦身

回执只留事实＋可用动作。逼稿/催封笔各一次的机制保留（架构完整性），文案删教学：

- 空手逼稿：`你还没有落笔。用 draft_append 演出，或 draft_write 一次交完，否则本拍无产出。`
- 催封笔：`已续写 N 段未封笔。写完就 draft_seal，没写完接着写。`
- 代收回执：`正文已代收为 draft_write。验收：{事实}。需要改就重交，不需要就结束（本卡格式块由谢幕注入点名）。`
- beat_plan 受理：`计划已接受（N 条路标）。`
- 零思考/连发/未修违规三种拒收回执随门禁一起删除。

## 4. 新建机制（三件）

### 4.A 默认预设文件（D1/D5 的承接者）

- 仓库自带 `presets/默认.json`（正常 RP 预设格式，随包发行）：内容＝现 assemble.ts 兜底文案的预设化改写（视角/排版/感官/推进/主权/忌AI腔/篇幅），用户可见、可改、可换。
- 装载规则：config.preset 为空→装默认预设。`presetActive` 恒真，assemble.ts 全部 presetActive 分支消亡。
- 用户预设在场→默认预设完全不装（不叠加）。

### 4.B 输出合约＋谢幕注入

合约数据形（`.liyuan/output-contract.json`，装配报告同级）：

```json
{ "modules": [
  { "tag": "state1", "source": "card", "form": "pair", "hint": "字段随剧情更新" },
  { "tag": "catsay", "source": "preset", "form": "pair", "hint": "咪咪点评" }
] }
```

- **v0 供数**（M-R1）：由现有 cardStatusBarFormats＋extractDraftRules.statusBarTagGroup 生成——识别器**冻结、只降不升**，作为过渡数据源；合约文件用户可改，改了以文件为准。
- **v1 供数**（M-R4 首件，8/11 落码 `src/stage/contract-declare.ts`）：装载期一次性模型声明（读卡＋读预设启用块＋卡内世界书→写合约；缓存按卡+预设+开关指纹落 `output-contract.declared.json`），声明成功即替换识别器供数；失败静默回退 v0，本进程不重试同指纹。form 增设 `fence`（``` 围栏块，tag 存名称）——围栏式状态栏直丢（8/10 已记录缺陷）由此获得机制解。谢幕点名标签改为 hint 供给（署名数据；无 hint 沿用 v0 惯例），实弹依据：8/11 手改合约点名 `<options>` 实验证实「点名→稳定输出」。
- 谢幕注入消费合约（2.3）；显示层折叠/历史剥离（FORMAT_STACK_TAGS/historyStrip）逐步改为从合约推导（M-R5）。
- 时序：seal（或兜底封笔）→ 谢幕注入 → 该轮 text 通道产出经 mergeFinalText 拼接落树。

### 4.C skill 一等素材位

- 目录：工作目录 `skills/<name>/SKILL.md`（agentskills.io 布局原样：frontmatter name+description 必填，scripts/references/assets 可选）。
- 装载器：扫描 frontmatter→L1 索引进 system `# 可用 skill`；description ≤1024 字符只写触发条件。
- 读取工具：`skill_read(name)`（writing_guide 改造：从「拆层 D/E 内存 Map」改为「文件优先＋拆层进口兜底」，主题制升级为名称制）。
- 常驻档：frontmatter `metadata.resident: "true"` → SKILL.md 正文随 system 常驻（预设留驻区之后）——「全程禁令小包」的送达方式。
- 进口通道（M-R4）：拆层 D/E 产物落成 `skills/imported-<preset>/` 文件（用户可见可删），不再只存内存。

#### 4.C.1 库的具体形态与勾选映射（8/10 补定）

**双库＋自写，三个来源并列入同一 L1 索引：**

- **默认库**（梨园发行，M-R3 手写）：6–10 个场面域包（打斗/NSFW/对峙谈判/群像/静场抒情/开场收场…），全拉取式。一包＝一个场面的完整方法论（触发表＋核心写法＋示范段＋反模式表）。
- **进口库**（每份预设一个目录，M-R4 分拣产物）：`skills/imported-<预设名>/`，一份预设产出约 **2–5 个包**：
  - `resident-rules/SKILL.md`（`metadata.resident: "true"`，1 个）：该预设全部「全程禁令/短文风规则」**原文汇编**，逐条标注来源块名（署名）；随 system 常驻。
  - `<主题>/SKILL.md`（拉取式，若干）：场面性方法论按主题归组（沿用拆层 topic 分类学），**正文＝原文条目，只组织不改写**；frontmatter 的 description（触发面）由声明步的模型撰写——预设原文没有「何时用」，触发面缺失正是进口素材的先天残疾，在声明步修复。
- **用户自写**：直接放 `skills/<name>/`。

**粒度裁决**：不是一包全装（无触发面——「写作」永远相关＝永远匹配不上），也不是每条一包（索引膨胀＋条款离开语境不成方法论；对照 Codex 索引硬预算 2% 上下文/8000 字符）。

**勾选映射**：**块→文件，勾选→启停开关，不做内容拼装。**预设界面停用某块 → manifest 该块 `enabled=false` → 装载器跳过对应文件/条目；skills 页签同样可整包/单条启停（对齐 config.disabledLore 既有交互模式）。内容永远是署名原文件，开关只决定装不装——错了错在一张看得见的开关表上。

**重叠不去重**：默认库与进口包同题（如都有 NSFW）→ 并列入索引，读哪个归模型，用户可停用任一；不做自动去重/合并（识别器回头路）。
