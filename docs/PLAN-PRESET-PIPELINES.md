# 预设双管线改造：输入侧拼接 + 输出侧标签渲染

> 2026-08-14 定稿。经过一整窗口反复试错，终于把「预设到底该怎么处理」捋清。本文档是下个窗口实施的规格，两条任务、一套贯穿原则。

## 一、背景与核心结论

预设本质是**「用散文 + 标签写给酒馆无状态模型的装配程序」**。它在酒馆里靠两条管线运转，梨园之前没把这两条分开，导致混在一起反复出错：

| 管线 | 管什么 | 酒馆怎么干 | 梨园该怎么干 |
|---|---|---|---|
| **输入侧（拼接）** | 哪段字进提示词 | 每轮按开关用宏求值器重拼 | **模拟拼一次 → 静态提示词** |
| **输出侧（标签渲染）** | 模型吐什么、怎么显示 | 散文教模型 + 前端正则抠标签 | **回归酒馆 + skill + 工具渲染** |

一句话：**输入侧拼一次拿到成品；输出侧让模型自己认标签、调工具渲染。两条线分开，谁都不碰「标签名穷举」。**

## 二、地基：三类「标签」必须分清

这是捋清一切的前提。长得都像「包在符号里的字」，其实是三种完全不同东西：

1. **`{{...}}` 花括号宏** —— 酒馆**引擎**的装配逻辑。`setvar`/`getvar`（存值/吐值，实现开关单选）、`random`（随机句）、`{{//注释}}`（剥掉）、`trim`、`{{user}}`/`{{char}}`/`{{lastusermessage}}`（填真实值）。引擎求值完才发，模型看不到原样。

2. **`<...>` 输出标签**（`<content>` `<time_format>` `<branches>` `<meow_FM>` `<aftertalk>` 等）—— 给酒馆**前端正则**排版。预设用散文**教模型**「往 `<time_format>` 里放时间」，前端配同名正则把吐出来的框**抠出来、摘掉、渲染成 UI**。标签是「模型↔前端」两头约定好的协议。

3. **`<...>` 分节标签**（`<cot>` `<style>` `<pov>` `<tone>` `<Prism>` 等）—— **谁也不碰**，就是提示词里的小标题散文，给模型看层次。

## 三、判据（反复试错得出的，别再用情绪/文字长相判）

- **判「死没死」看字到没到模型**：到了就有作用（哪怕作用坏），没到才死。没到只有两种：①零字（空块/纯注释/`━━━` 架子）；②`setvar` 存的字没有 `getvar` 消费者。
- **判「留不留」看 bypass 谁**：bypass **模型**（破限/压力文本/人格/文风/模型适配）= 留，压力本身就是破限手段；bypass **酒馆 harness**（COT 台本/变量协议/输出格式标签）= 死，删。
- **去处只有六个**：提示词（纯文字）/ skill（必读·按需）/ 输出合约 / 参数 / 删 / 留档。

**分层删除**：层1 = 结构必死（空/注释/trim/空 setvar/架子标签），零判断、100% 安全；层2+ = 有字需判断，**逐条摊给用户定，不替用户拍板**。AI 判断和脚本名单已被证实不可靠。

## 四、任务一：输入侧 —— 模拟酒馆引擎拼接

**目标**：导入预设后，模拟酒馆引擎按当前开关**拼一次**，得到最终静态提示词；之后每开关一个条目就**重拼一次**、写入系统提示词。

**为什么**：
- 酒馆靠 `setvar`/`getvar` **每轮**按开关重拼提示词；梨园提示词是静态的，拼一次就够。
- 之前做的「纯文字化」是**逐块展开 `setvar`**，位置错了——酒馆语义是 `setvar` 块**自己不吐字**（只存值），由**后面别的块里的 `getvar`** 在另一个位置吐出来。正确做法是「**跑一遍装配、拿到拼好的成品**」，不是逐块展开。

**现成机制**：`src/preset-macro.ts` 的 `evalPresetMacros` 就是这套装配器（`setvar` 存 / `getvar` 吐 / `random` 抽 / `trim` / 注释剥除，跨块共享变量表、按序求值）。不用新造，**也不用扩**——见 §四之三 实测。

### 四之一、第一步不是拼接，是把存储换回原始酒馆 JSON

**现状（8/14 实测）**：`assets/presets/` 里 5 份预设**全部已是梨园私有格式** `{name, samplers, blocks[{id,name,channel,role,content,enabled,depth}]}`，仓库里**没有任何一份原始酒馆预设**。

导入期那次转换是**有损**的，丢掉的正是拼接所需的骨架：

- 酒馆的 `prompts` + `prompt_order` 被压平成一个 `blocks` 数组（顺序声明没了）；
- **marker 块全丢**（`chatHistory` / `charDescription` / `worldInfoBefore` / `worldInfoAfter` / `dialogueExamples` / `personaDescription` 等占位符）——marker 就是「世界书/角色卡/对话历史插在哪」的位置声明，**模拟拼接必须靠它定位**；
- `injection_position` / `injection_depth` 只剩一个 `depth` 字段，242 块里仅 2 块带它。

**所以任务一的步骤是**：① 预设存储换回原始酒馆 JSON，导入零处理（AI 分拣、逐块分类、通道判定一并退场）→ ② 实现 assembler，照酒馆自己的字段死板装配 → ③ 求值 → ④ 写入静态提示词。

### 四之二、拼出来的不是一段，至少是两段

实测 channel 分布 `system 62 / postHistory 180`：postHistory 在酒馆里是**对话历史之后**，位置语义与 system 不同，**拍平成一段会丢**。assembler 至少产出「历史前」「历史后」两段；marker 展开后可能更细。

两个静态性例外，明确处置：

- `{{lastusermessage}}`（全预设出现 1 次）每轮变，静态拼不住——要么每轮只重求值它所在的块，要么承认在 agent 架构下它无意义（梨园本来就有用户原文）。**实施时定，不要默默糊过去。**
- `pushplus` 是悬空 `getvar`（有 get 无 set），拼出来空串——**与酒馆行为一致，不用管**。

### 四之三、可行性实测（8/14，双人成行 v10.0，242 块）

| 项 | 实测 | 含义 |
|---|---|---|
| 宏名频次 | `setvar 338 / getvar 290 / random 46 / trim 30 / user 4 / addvar 1 / lastusermessage 1` | **零条超纲**，全在 `evalPresetMacros` 支持清单内 |
| setvar/getvar 键 | set 131 / get 104；set 无 get 28；get 无 set 1 | 28 个死值可按判据「字没到模型」判死 |
| role | system 238 / assistant 3 / user 1 | 少量非 system，assembler 要保 role |
| enabled | true 70 / false 172 | 开关是主要变量 |
| depth | 仅 2 块（0 和 1） | 本预设深度注入几乎不用；**但别的预设常用，assembler 不能不实现** |

**结论**：求值器够用，缺的是 assembler（marker / 顺序 / role / depth 这套装配骨架）。

### 四之四、关键边界（8/14 修正——原稿这里写反了）

**输出模块的散文照进提示词。** `📅丨日期卡片` 那 984 字**本身就是提示词**：开关一开，它进提示词教模型吐 `<time_format>`，酒馆前端正则再把框抠出来渲染——**没有第二套机制**。若把它拦在提示词外，模型不知道该吐什么，梨园就得自己重写一遍输出指令，那是「替预设作者思考」的堆叠（铁律一）。

**8/10 事故的根因原先也归错了**：根不是「状态栏进了提示词」，是梨园在预设之外**多加了一句自己的话**（「每拍在正文之后按同样的块结构输出」）。**进提示词是对的，加话是错的。** 梨园要退掉的是自己那套输出合约 / 谢幕注入 / 名单渲染，不是预设作者写的散文。

**开关一律触发重拼**：不分「文风块」还是「时间栏块」——它们在酒馆里是同一种东西（提示词块），梨园不再自己分类。开关 → 重拼，只此一条路径。

**已知代价（认下来，别以后当 bug 查）**：重拼会改 system 头部字节 → **前缀缓存失效**。`src/preset-macro.ts:85` 把 `random` 做成内容寻址钉死就是专为缓存稳定；开关是低频动作，代价可接受。

## 五、任务二：输出侧 —— 回归酒馆 + skill + 工具渲染

**现状问题（已核实，不是按形态是按名字）**：现在状态栏渲染是**名字名单穷举**，违反铁律三：
- 后端 `src/postprocess.ts` 的 `PANEL_NAME_RE`（`status`/`statusblock`/`state_N`/`状态`/`状态栏`/`人物状态`/`场景状态`…）；
- 前端 `web/src/statusBlocks.ts` 的 `isPanelTagName` + `LABEL_BY_NORM`（标签名→中文标题字典）。

`state1` 能渲染纯粹是因为撞上 `state_\d+`，`options`/`thinking` 同理。补标签 = 往这张名单加名字，下一个作者发明 `<world_map>` 又加一个，无穷无尽。

**方向（已定）**：回归酒馆，让标签**随正文输出**（所见即所得）；用 **skill + 工具渲染**，彻底摆脱名字名单。

**方案三件**：
1. **必读渲染 skill**：教模型「发现标签就思考它是什么、调用渲染工具渲染」。skill 的读取发生在输出前（所见即所得）。
2. **受理门兜底**：正文里残留未渲染标签就拦下、回执指路，**强制**渲染工具调用——自愿动作会失败（已有实锤：writing guide 读了 0 次、「内容在场不顶用」）。
3. **渲染工具**：模型调它，声明「这是时间卡/这是选项」，工具照声明渲染。

**关键原则**：**认形态不认标签名**。渲染工具统一按三种形态（成对 `<tag>…</tag>` / 自闭合 `<tag/>` / ` ``` ` 围栏块）处理，**不给每个标签写专属渲染器**（那又回到穷举）。标签名从「源码名单」降回「模型自己判断的数据」。

**富渲染（播放器/复杂 HTML）**：梨园不实现专属渲染器，正确做法是**降级成围栏块显示，或交给卡作者自带的 frontend**，不做则不做。

## 六、已确认的架构事实（别再推翻）

- 状态栏是**输出模块**：它的**数据与渲染**不在提示词里（梨园不往提示词塞状态栏内容），但**教模型输出它的那段散文**就是提示词的一部分（预设作者写的那一块）。8/14 修正：原稿只写了前半句「从来不是提示词的一部分」，导致 §四 把散文也一并拦在了提示词外。
- 谢幕注入 = 记账后按合约清单点名输出模块（`output-contract.json` + `curtainInjection`）；将来让位给 skill+工具渲染。
- 合约缺「位置」维度（`form` 只有形态，没有「开头/结尾/正文穿插」）——回归酒馆的「标签随正文输出」后，位置问题自动消失，不用补。
- `mergeFinalText` 声称按形态认块，但前端 `statusBlocks.ts` 实际是按名字名单。
