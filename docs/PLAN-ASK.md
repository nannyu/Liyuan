# PLAN-ASK：ask 重开——开局收集 + 续写裁决

2026-08-11 立。承 PLAN-RECTIFY（M-R1 删除四门禁与轮次卡后 ask 失去全部送达席位）与 8/11 凌晨 skill 数据侧路线实弹失败（收笔二分 + 开拍第四问「一点变化没有」，已撤销）。本文档是契约：文案即规格。

## 0. 定案依据（用户 8/11 拍板）

1. **「扮演中突然意识到该 ask」不现实**——ask 的送达必须挂在结构性时刻上，不赌模型自觉。superpowers 的信息收集印证：提问是流程阶段（brainstorming 硬门），不是临场美德。
2. **开局问的旧禁令撤销，理由变了**：旧版模型在思考里排练正文后问剧情，用户看不见那堆隐形剧情、无从判断（PTSD 来源）；现行模型先扮演用户输入再续写，开局问的是**用户自己输入的剧情走向下的细节**，判断依据全在用户手里。变的不是模型，是提问所依赖的上下文从「模型私有」变成了「用户共有」。
3. **续写 ask 不属于 skill**：续写是 harness 确知的时刻（路标演完 + 字数事实），剧情走向判断是续写的固有成分——ask 在此不是新增动作，是把这个必然发生的判断的裁决权还给用户。旧版（v1.3.0）实弹验证有效，用户点名恢复其措辞。
4. **机械化的是时机，判断归模型**（8/11 斟酌定案）：两版行动层从来都归模型（世界书走向明确就不问＝正常工作，不杀）；差的是时机层送达可靠性。全机械强制 ask 判为坏方向（退化成盖章）。
5. 密度档位：**判定一次性 + 堵抢跑 seal 洞**。备选（实弹送达仍不足时再议）：ask 一句进进度行（每轮替换、不累积）。

## 1. 板块一：开局规划 ask（收集阶段）

### 1.1 收集判据（三条同时满足才问）

1. **由用户输入直接引出**——扮演这句输入绕不过去的空位（例：「user 被谁买下了」→ 买主性格），不是模型发散的远景。
2. **决定分岔**——变量取不同值，这拍走向明显不同（性格温和 vs 残暴＝两拍不同的戏）；不分岔的顺着演。
3. **卡与世界书查不到**——查得到先查（规划轮既有探索步骤），查不到才问。

反面清单（不收集）：装饰细节、可查到的设定、用户角色自己的内心与选择（那是用户玩出来的，问了是抢戏）。

一次一问（ask 单问题带 2–4 选项）；多个变量只问过判据的、最关键的先问。

### 1.2 投放：规划卡改写（既有注入通道内改写，非新增）

`engine.ts` `PLAN_CARD` 改为（文案即规格）：

> 【第 1 步·规划】本拍还没有计划。读题、探索（工具自取）；用户这句输入引出的未定变量——取不同值这拍走向会分岔、且设定里查不到的——先 `ask` 请用户定，再用 `beat_plan` 列路标。没有戏的拍可 `draft_write` 一次交完；用户本轮在求方向/递笔的，直接 `ask`。

送模文案净增约 40 字——铁律一判据下属违律形状，**由用户点名豁免**（8/11「写好文档开始执行」；8/11 凌晨已实证 skill 清单式投放不发火，规划卡是唯一结构保证首轮送达的既有席位）。

### 1.3 连带：ask 工具描述②改写（tools.ts）

「变量触发（演出中、落笔前）」整段改为「开局收集（规划阶段、列路标之前）」；**删除反向教学句**「变量类拍板宜有上文：等用户看到段落上文再问，才好选」（其正当性已被 §0.2 时机论证取代）。三判据入描述，动态判断（不因新而问）与禁代写用户档案两句保留。改写后该段不得长于现文。

### 1.4 不动的

`skills/写作/SKILL.md` 不加开局收集条目（8/11 撤销的第四问＝同判据清单式投放实弹失败，不重试）；收笔节「拿不准的时刻用 ask」一句保留。

## 2. 板块二：续写 ask（裁决时刻）

### 2.1 判定注入文案改写（恢复 v1.3.0 实弹验证句）

`engine.ts` `verdictInjection` 改为：

> 【判定】路标已演完，正文约 N 字（目标 min–max）。续写、`ask`、或 `draft_seal` 收笔——你判断；下文涉及 {userName} 的行动或选择，先 `ask` 再动笔。

（需接入 `userName`——`o.wsDeps.userName` 既有字段。）

### 2.2 抢跑 seal 时序保证（日程机制，非注入）

8/11 实弹实锤：判定注入是唯一 ask 席位，模型抢跑 `draft_seal` 可整个跳过。堵法与「记账注入在 seal 后第一件事」同类——日程时序保证：

- **模型调用的** `draft_seal` 到达时，若判定尚未送达（`!verdictInjected`）、路标存在且全演完、稿身非空：**本次 seal 不受理**，回执即判定文案（同一席位、提前经工具回执送达），置 `verdictInjected = true`。
- 下一轮模型再调 seal → 照常受理（一次性保证，不成循环）。
- **不拦**：无计划的分段拍（判定本就不发，「路标已演完」不成立）、路标未演完的中途封笔（旧行为保留）、harness 内部兜底封笔（`engine.ts` M-E 兜底、停手轮自动 seal）与 `draft_write` 全量交稿的天然封笔。

### 2.3 不动的

进度行保持纯事实零 ask 字样（密度备选留待实弹）；扮演轮次触发（写作中途的变量 ask）按用户指示押后，不在本契约范围。

## 3. 验收

- 测试：规划卡含收集句；判定文案含 ask 裁决句；模型 seal 抢跑被判定回执拦下、二次 seal 受理；内部兜底 seal 不被拦。
- 实弹（合入后）：开局收集在「输入引出未定变量」的卡上发火且问的是用户输入的展开细节；世界书走向明确时续写不滥问；抢跑拍里判定必达。
