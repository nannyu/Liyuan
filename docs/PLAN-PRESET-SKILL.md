# PLAN-PRESET-SKILL：预设→标准 skill 完全转换

2026-08-11 立。用户定案：「预设转换 skill 这条路完完全全做好，不希望再因预设卡住」。直接动因：①stale override 让第一人称遮蔽第三人称选择十余日；②禁八股/比喻 1079 字在验收退役后失去去向整体蒸发；③splitTable 按 8/03 快照冻结（第一人称写死常驻、第三人称不在表）；④「预设变 skill」实际只转了 E/D 类 3400 字且投放在已证死的拉取通道。

## 0. 原则

1. **无一蒸发**：预设每一块（含 enabled=false、含退场类）都投影成后端可见的标准文件。退场不是删除，是「标记为退场、写明理由、你能看到」。
2. **开关单一真源**：块的 enabled 只活在预设（override 优先的有效预设）。skill 管理器的开关是同一比特的第二个视图——两边任一处切换都写同一个地方，不存在第二份需要对账的状态。
3. **分拣结果=数据**：块→去向的判定落成 manifest（可看可改可纠错），生成在预设装载瞬间自动发生；判定器错了改的是一份数据，不是一段正则行为（铁律三替代形态）。
4. **五分法不变**（PLAN-RECTIFY 问题二定案）：破限/边界→留驻原文原序；文风/方法论/场面→skill；机制已覆盖→退场；输出模块→输出合约；samplers→参数。skill 化只是五分之一，A 类破限永远不做成 skill。

## 1. 文件布局（标准 agentskills 形态，后端全可见）

```
skills/预设-<presetSlug>/
├── SKILL.md            # 本预设 skill 包的索引与说明（name/description frontmatter）
├── manifest.json       # 块→文件→去向→预设块id 映射（分拣数据，可手改）
└── blocks/
    ├── 01-👻TG推荐文风.md      # 每块一文件：frontmatter(name/nature/fate/channel/presetBlockId)+原文
    ├── 02-第三人称视角.md
    └── …（含关闭块与退场块，一个不少）
```

- 文件内容=块原文零改写（署名归预设作者）；frontmatter 记 nature(A-I)/fate/来源块 id。
- enabled 不写进文件（避免第二真源）——运行时从有效预设投影。
- manifest 带预设内容指纹：预设变（换文件/改块）→ 装载时自动重新生成；用户手改过 fate 的条目保留（gen 副本比对，同 output-contract 模式）。

## 2. 装载期转换（导入一瞬间后台就有）

`materials.ts` 装载有效预设后：指纹不匹配（或目录不存在）→ 立即生成/更新上述目录。分拣判定：既有 splitTable（冻结名单，只读不加行）→ 命中用表；未命中走四类兜底 classify；两者都只产 manifest 数据。（后续升级位：装载期一次性模型声明替代兜底——判定升级不改文件格式。）

## 3. 运行时消费（引擎只认 manifest+enabled）

每拍装配时按「有效预设 enabled ∩ manifest fate」消费：

- fate=resident → 常驻区（原文原序，现 presetResident 通道）；
- fate=skill:<topic> → 拉取包（skill_read 名单），主题聚合；
- fate=contract → 输出合约候选（状态栏/选择框/点评类，M-R4 后续接）；
- fate=drop → 不送模（但文件在、报告在）；
- samplers → 参数投影照旧。

旧路径（materials 内联拆层）切换为读 manifest；行为回归基线=现有 preset-assembly.json 报告。

## 4. 前端（PowersPanel skills 页签新增「预设 skill」区）

- 按预设分组列出全部块条目：名称、去向徽标（常驻/skill:主题/合约/退场+理由）、开关。
- 开关=写预设草稿（同 PresetPanel 的 enabled 位）→ 双向同步天然成立（两个面板读写同一 override）。
- 条目可点开看文件内容（后端文件路径直给）。

**双人成行 v10.0 青云上 Agent 版**（245 块，启用 67）：`━━━━` 分隔条分组 + setvar 弹药库 + 聚合枪膛（style/Prism/COT/Core 全 postHistory）。**41 个文风块已被预设作者自己改造成 skill_read 指针**——预设生态已在自发走 skill 化，方向铁证。互斥组 12+ 个（人称 9 选、基调 7 选、push_rule 4 选、思维链三家、前端渲染 3 选…）。启用面 H 壳+I 分隔条占近半；死变量 2 处。E 类 NSFW 部位特化 8 块=天然 skill 子主题。状态栏/选择框/日期卡/摘要栏/双子札记/音乐面板=输出合约领地 7+ 块。

**对转换器的校准结论**：①三表都在（BUILTIN_SPLIT_TABLES）但按快照冻结，互斥组成员不全在表——兜底 classify 必须兜住表外块（已验证：第三人称走兜底→常驻B）；②互斥组是三份预设共有的一等结构（人称/文风/基调/推进/COT），manifest 需 group 字段（v1 由分析报告手工回填，装载期声明升级后自动）；③输出格式类块（状态栏/选择框/摘要/点评/前端渲染）三份都有=输出合约候选池；④「预设作者自己已经在写 skill 指针」（双人成行）=块→skill 文件的映射与生态演化方向一致。
